# 开机选择器：电源键进 DSH

主人 2026-11-26 的要求：我们一套系统、原厂一套系统，不占用原厂生态，在设备上就能切换，不需要 Mac。原厂的主菜单图标必须由 M5Stack 官方放进正式固件，见 [应用中心](app-center.md)。主人的 ESP-NOW 摇杆在开机启动器阶段收不到（那时还没启动无线），原厂运行时也没有切换系统的功能，所以用不了。

## 想要的行为

| 操作 | 结果 |
|---|---|
| 正常开机，不按任何键 | 和现在完全一样：按原厂的启动记录启动原厂（默认） |
| 开机后 3 秒内（屏幕亮之前），短按一下电源键 | 进入 DSH（ota_0），只进这一次 |
| DSH 里点 Home，或者再重启 | 回到原厂 |
| 软件重启、看门狗重启、从睡眠醒来 | 不检测手势，照原厂规则启动 |

开机按的那一下，电源芯片当成「开机」处理，不会记成按键；所以开机后再按的那一下才算数（真机诊断确认，见下文）。最初的设计是 1.5 秒内按两下、并用充电灯快闪提示，主人试了觉得太难操作，在 StackChan 上也看不到那个灯，所以改成了现在这样。

## 怎么做（不碰原厂程序）

- **只换二级启动器**（Flash 0x0–0x8000）。用原厂启动器同一版本的 ESP-IDF v5.5.4、同一份配置编译。原版启动器的代码一行不改，只定义它预留的挂钩函数 `bootloader_after_init`：初始化完成、选择分区之前调用一次。
- **手势只在冷启动时检测**（芯片上电复位）：
  1. 用 GPIO12/11 软件模拟 I2C，连电源芯片 AXP2101（地址 0x34），先确认芯片身份寄存器 0x03 读出来是 0x4A。读不到就跳过，照原厂规则启动。
  2. 记下充电灯寄存器 0x69 的原值，改成快闪作为提示，窗口结束后写回原值。
  3. 清掉电源键状态寄存器 0x49 的短按位（bit3）和长按位（bit2）：往对应位写 1 就清除，和 M5Unified 的 `getPekPress` 一样。然后在约 1.5 秒窗口里每 10 ms 读一次，短按位置上就计一次并清掉，计满两次就接受。
- **接受手势后，写的和 Mac 的 `enter_dsh.py`、已审查的试装完全一样**：
  1. 用原版启动器自己的函数读分区表，逐项核对 otadata、ota_0、ota_1 的位置和大小（和旧选择器一样）；
  2. 核对 ota_0 里是有效的 DSH 镜像：镜像校验通过，版本标识以 `dsh-agent-` 开头；
  3. 核对原厂是已确认的运行槽；
  4. 在另一个 OTA 扇区写一条「原厂序号 + 1、状态 NEW」的记录，读回确认。

  然后原版启动器照常往下走：看到这条 NEW 记录，标成 PENDING_VERIFY，启动 DSH。之后的回退、Home 返回都是已经在真机上验证过的路径。任何一项核对不通过就什么都不写，照原厂规则启动。
- **代价：** 每次冷启动多等约 3 秒；软件重启不受影响。

## 依据

| 事实 | 来源 |
|---|---|
| AXP2101 地址 0x34；中断状态 0x48–0x4A，使能 0x40–0x42 | XPowersLib `AXP2101Constants.h`（`17132a5`） |
| 0x49 的 bit2 是长按，bit3 是短按（`PKEY_LONG_IRQ = _BV(10)`，`PKEY_SHORT_IRQ = _BV(11)`，24 位掩码的中间字节） | XPowersLib `XPowersParams.hpp` |
| 读取并写 1 清除，不需要先打开中断使能：`val = readRegister8(0x49) & 0x0C; if (val) writeRegister8(0x49, val);` | M5Unified `AXP2101_Class.inl` 的 `getPekPress`（`96576a1`） |
| 0x69 充电灯：`val &= 0xC8; val \|= 0x05`（手动控制），`val \|= mode << 4`（模式写在 bit4–5） | XPowersLib `XPowersAXP2101.hpp` 的 `setChargingLedMode` |
| 原厂启动时写 0x69 = 0x35、0x27 = 0x00；原厂代码里没有读写 0x49 | 原厂 `stackchan.cc` |
| 原版 v5.5.4 启动器在初始化后调用 `bootloader_after_init`（弱符号） | `components/bootloader/subproject/main/bootloader_start.c` |
| 内部 I2C：SDA GPIO12，SCL GPIO11 | 原厂 `hal/board/config.h` |

还要上真机确认：
- 开机那一下是否会被记成短按；
- 充电灯在机身上是不是看得见；
- 两下之间的间隔是否在电源芯片的短按判定时间内（原厂设置 0x27 = 0）。

## 验证步骤（上真机前）

1. **主机测试：** 启动记录的判断（和 `enter_dsh.py` 一致），以及按键计数状态机：0、1、2 次短按，开机按住，读失败。
2. **构建：** 和原厂启动器同版本、同配置，产物大小不超过 0x8000。和原版对比，只多出挂钩函数和它的代码。
3. **QEMU：**
   - 用 Sion 的整片快照，不做手势：启动原厂，整片字节不变；
   - 用调试器把手势判定改成「接受」：写入那条记录，启动 ota_0；
   - 回退后再冷启动：回到原厂。
4. **上真机写启动器前，先给主人看：** 确切文件、地址（0x0–0x8000）、写之前的整片备份、恢复方法（ROM 下载模式写回原启动器）。主人同意后才写。

| 主机测试 | `scripts/test_boot_selector_pek.py`：启动记录 10 种情况（和 `enter_dsh.py` 一致）、按键计数、DSH 版本判断，全部通过 |

| 步骤 | 结果 |
|---|---|
| 写入启动器 | `scripts/install_boot_selector.py`：一次 ROM 连接里核对身份和 3.3 V 电压绑定，开头 64 KiB 读两遍、一致后备份，确认现有启动器就是要替换的那个，写入并整块读回。第一次写之前的原版启动器区域备份在 `.local/backups/sion-selector-before-20261126T031844Z/` |
| 第一版（按两下、1.5 秒、闪灯） | 不按时启动原厂（通过）。按两下没进 DSH，主人觉得太难操作，也没看到灯闪 |
| 诊断版 | 在 0x1F000（未分配的空隙）记录每次开机的情况：<br>① 复位原因是上电，I2C 300 次读取全部成功，芯片身份 0x4A；<br>② 开机时按住电源键 2 秒，0x49 一直是 0xA0（接入电池和 USB 的中断），电源键相关的位一次都没出现：开机那一下不会被记成按键；<br>③ 0x41 原值 0xFC，短按和长按的中断本来就开着；<br>④ 充电灯寄存器原值 0x05（关），在机身外看不到；<br>⑤ 改成开机后再短按一下：约 0.5 秒时读到短按，写入序号 3，启动器标成待确认，启动 DSH |
| 正式版（`be55a70c…`，26,176 字节） | 按一下、3 秒窗口、不碰灯，QEMU 4/4。真机：不按时进原厂，按一下进 DSH（主人确认）。诊断扇区 0x1F000 已擦回全 0xFF |

## 风险与恢复

- 写启动器时如果断电，设备起不来，但芯片 ROM 里的下载模式是固化的，不会被写坏。长按 RST 进下载模式，从整片备份写回原启动器即可，这次会话里已经多次经这条路恢复。
- 原厂的应用 OTA 只写应用槽和启动记录，不碰启动器，选择器会一直保留。用 M5Burner 整包重刷会把启动器换回原厂的，那样只是失去这个手势，原厂本身不受影响。
