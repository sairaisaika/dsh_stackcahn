# 下一次真机：合并测试清单（2026-11-26 起草，11-27 改成引导式）

主人的要求有两条：要上设备的测试攒在一起一次测完；**每一次测试都要很有用，测一次就能拿到很多信息、推动很多开发。**

这一页按这两条来设计：

- **机器人自己出题。** 主人不用看终端，只看机器人的屏幕。屏幕上写一道题，主人点一下屏幕作答，左、中、右三分之一代表不同答案。点的位置、角度和用时都自动记下，点屏幕本身也顺带测了触摸屏。
- **能自动测的全部自动测。** 喇叭和自己的麦克风互相测，Mac 念句子给机器人听，记录电流和姿态。主人只在需要眼睛、手的地方出场。
- **一条命令出报告。** 测完我运行 `scripts/probe_report.mjs`，报告直接给出结论和数字，不靠回忆。
- **每项都写明结果会推动哪项开发**（见最后一节），测试是为开发服务的。

操作顺序尽量少切换模式（原厂 ↔ DSH、进 ROM）。结果记进[验收记录](validation.md)，再回填各专题页。设备当前状态以开测时实际看到的为准。

## 3. 引导式身体测试 A（约 12 分钟，主人只看屏幕、点屏幕）

Claude 先在 Mac 上关掉 DSH 的语音服务（探针和语音服务不能同时占用连接，配对租约会拒绝第二个），然后运行：

```bash
node scripts/body_probe.mjs --out <证据目录> --steps scripts/sessions/session-a.steps
```

剧本在 [`scripts/sessions/session-a.steps`](../scripts/sessions/session-a.steps)，共 142 步、31 道屏幕题。分段如下：

| 段 | 主人做什么 | 自动记录什么 | 回答的问题 |
|---|---|---|---|
| 0 基线 | 什么都不做 | 全部传感器静止 5 秒，房间底噪 3 秒 | 每个传感器的零点和噪声，后面各段都和它比 |
| 1 声音自检 | 听，答 2 题 | 喇叭在 5 档音量和 6 个频率下发声，同时录**麦克风和回声参考两个通道**；3 声短音专门看结尾；满音量时的电流 | 音量对应的实际电平；哪档开始削波；**结尾重复是否在设备端**（看参考通道）；麦克风听到自己喇叭多响（回声消除、插话打断的前提）；从发送到出声的延迟；喇叭耗电 |
| 2 听写 | 保持安静 | Mac 念 4 句已知的话（唤醒词、提醒、指令、数字串），机器人录下 | 机器人的麦克风在实际距离上能让 Whisper 认对多少（字错率）；唤醒词的录音电平 |
| 3 灯环 | 12 次：朝亮着的那颗灯，点屏幕边缘 | 每颗灯对应的点击位置和角度 | 12 颗灯各在机身哪个位置，一次补齐映射表 |
| 4 环境光 | 手盖住、拿开 | 两段光照和接近读数 | 传感器在哪，能分辨多大的变化 |
| 5 红外 | 用遥控器按几下；用手机相机看发射 | 收到的编码；发送回执；主人答看没看到闪光 | 收发是否都通 |
| 6 NFC | 放卡、拿开 | 5 次放卡读、2 次空读、卡片到达和离开事件 | v78 的重试是否有效；空读报「没有卡」而不是总线错误 |
| 7 相机 | 站正前方、左一步、右两步 | 3 张照片 | **相机第一次真机拍照**：方向、颜色、曝光；三张照片里脸的位置，评估头耦合透视能不能用机身相机找人 |
| 8 转头 | 先看它自由转，再轻轻扶住头 | 两段电流和姿态，扶住时读回舵机 | 堵转规则有没有生效（上次没挡住）；转头和堵转时的电流，顺便看出电流的正负号 |
| 9 鱼缸 | 看 3 次转身，各答顺不顺 | 存帧结果、每档时间线的结果 | 只推人物小块时 30、45、60 fps 哪档最顺 |

注意：

- 音量只在这次会话里改，结束时设回 60。设备设置页的「保存」不碰。
- 相机许可默认是关的。如果第 7 段报许可错误，报告会写明，下次先在设备上打开许可再拍。
- 每段失败不会中断后面的段，失败原因逐条记进报告。

测完 Claude 运行：

```bash
node scripts/probe_report.mjs <证据目录> --whisper
```

报告包括：失败清单、静止基线表、声音分析表（自动判断哪个通道是回声参考，算出延迟、电平、多出的时长和额外声段）、全部问答、灯环位置表、NFC、红外、相机、转头电流、鱼缸、听写字错率。`--whisper` 用本机 whisper-cli 离线识别，不上网。

## 4. 回到 DSH 语音，说 3 句已知的话

Claude 重新打开 DSH 的语音服务。主人依次说：

1. 「Sion，你好」

| 做法 | 通过 |

| 按 Home 或重启 | 原厂界面，原厂语音能回答 |

## 测完能推动哪些开发

| 测试得到的信息 | 接着做的开发 |
|---|---|
| 灯环 12 颗的位置 | 写进身体描述，DSH 能说「左眼旁边那颗」；做方向性的灯光表情（声音从哪边来就亮哪边） |
| 参考通道上结尾有没有重复 | 有：修设备端播放缓冲，删掉 Mac 侧补的静音；没有：问题在功放或 Mac，换方向查 |
| 麦克风听到自己喇叭的电平和延迟 | 决定插话打断怎么做：设备端回声消除、Mac 端用参考通道相减，或播报时只认「停止」 |
| 各档音量的电平和刺耳点 | 给音量设上限，做一条平滑的音量曲线 |
| 听写字错率、唤醒词电平 | 调 VAD 和唤醒门槛（soak 里约 2 小时有 77 次误唤醒识别）；决定要不要换更大的 Whisper 模型 |
| 堵转时的电流和是否放弃 | 修堵转规则：「离目标还远、位置连续不变」就提前释放；确定电流阈值和正负号 |
| 三张照片 | 相机可用就接 DSH 拍照工具的真机验收；脸能找到就用机身相机做头耦合透视的头部追踪，不必另加摄像头 |
| 鱼缸 30/45/60 fps 的手感 | 确定帧率，决定存帧数量和渲染预算 |
| NFC 放卡和空读的结果 | v78 通过就写成常驻；卡片含义交给 DSH 记 |
| 红外收发 | 通了就让 DSH 学遥控器（空调、电视），这是身体对外的第一个执行器 |
| 第 4 节的延迟 | 和 soak 数据一起，定下一轮语音延迟优化的目标 |
