# Open a verified DSH App Center installation from the launcher

The default-off patch targets public StackChan v1.6.2 commit `28b9f0c8bd6acd81cb3c70f1a93c3e373b39d400`. Apply [`home.patch`](../m5stack-app-center-home/home.patch), [`reopen.patch`](../m5stack-app-center-reopen/reopen.patch) and [`shortcut.patch`](shortcut.patch) in that order. In the ESP-IDF v6.1 build, append their defaults files in the same order after the upstream defaults, then set `CONFIG_STACKCHAN_DSH_CATALOG_ID` to the publisher-assigned positive numeric App Center ID. The bundled value `31337` is for the build and simulation fixtures. The service contract for App Center Open still applies, including the HTTPS `reopenImageSha256` for the exact companion image. Build that companion against the output of this particular receiver build using `scripts/prepare_agent.py --app-center-baseline … --app-center-home-stock …`.

Select Download or Open in the matching App Center listing once to associate the installation with the menu shortcut. The receiver records the factory and companion validation hashes in one `app_dsh_menu/launch_v1` NVS blob after successful SDK boot selection, a valid DSH image descriptor and an exact match to the catalogue digest. The launcher can then verify and select the same companion entirely offline. If no record exists, the OS has an update in progress, or a firmware change invalidates either digest, it shows a status with a Home button. Setup → Apps → App visibility has a separate DSH.AGENT switch using `feature_toggles/dsh_visible`. Home uses the existing one-time launcher return.

The shortcut verifies the running factory image by streaming its Flash bytes into ESP-IDF's SHA-256 implementation and comparing the result with the appended image digest. This avoids remapping executable pages during the check. The inactive DSH image continues through the SDK partition-hash and OTA selection APIs. The record format and exact-image requirement are unchanged.

The public source requires an official receiver that retains production authentication and an official matching App Center listing for a production rollout. This experiment uses the original bootloader and partition layout. Before release, verify first use, offline reopen, update handling, launcher visibility, factory voice and the existing binding on the same device. Host and ESP32-S3 fixture reproduction are linked in the [project Wiki](../../wiki/app-center.md#app-center-应用的主菜单快捷入口).

Run the shortcut logic on the host with `python3 contributions/m5stack-app-center-shortcut/tests/run.py --stock <patched-checkout>`. The target rehearsal uses `scripts/audit_app_center_shortcut.py prepare` to copy the exact storage and selection helpers into the probe, then `idf.py -C <prepared-probe> build` and the script's `audit` subcommand with the saved Flash capture and paired DSH binary. Use `audit --help` for paths. The rehearsal writes only temporary virtual Flash copies.
